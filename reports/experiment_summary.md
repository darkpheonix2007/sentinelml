# Historical per-feature alert rule — measured results

This is the **before** rule. It predates the BH correction, persistence requirement, and bootstrap degradation check. Use [alert_rule_comparison.md](alert_rule_comparison.md) for a paired before/after alert comparison; do not treat this report's degradation labels as equivalent to the revised labels.

Run: 30 repetitions per condition, 1,560 batches total, using baseline `baseline-20261030T130806128508Z`. Batch sizes were 100, 250, 500, and 1,000. The complete per-batch CSV and JSON summary are generated by `python -m sentinelml.cli experiment --repetitions 30`; this report records the measured development run.

## Main finding

The monitor is useful as an educational prototype, **not ready for unattended alerts**. Across stable batches, 43.3% triggered at least one alert (52 of 120). Against the study's threshold-defined degradation outcome, any-alert precision was 48.1% and recall was 75.2% (620 true positives, 668 false positives, 204 false negatives, 68 true negatives). These values should not be described as production reliability estimates.

| Scenario, strength | Batch size | Any-alert rate | Degradation rate | Mean F1 |
|---|---:|---:|---:|---:|
| Stable | 100 | 43.3% | 16.7% | 0.575 |
| Stable | 250 | 33.3% | 23.3% | 0.548 |
| Stable | 500 | 60.0% | 0.0% | 0.552 |
| Stable | 1,000 | 36.7% | 0.0% | 0.553 |
| AGE shift, 1.0 | 500 | 100.0% | 0.0% | 0.555 |
| Repayment shift, 1.0 | 500 | 100.0% | 100.0% | 0.383 |
| Label shift, 1.0 | 500 | 60.0% | 100.0% | 0.406 |

The AGE shift demonstrates alerts without observed quality loss for this configuration. The repayment shift shows a strong predictive-feature perturbation accompanied by lower F1. The label-only shift leaves features unchanged; its 60% alert rate matches the stable 500-row rate, so input monitoring did **not** detect the label change as such.

## Interpretation and next improvements

“Any alert” includes feature-level and data-quality warnings. It is more sensitive than the aggregate drift flag, which requires 20% of features to cross thresholds; for example, a single shifted feature can cause an individual warning while the aggregate flag remains false. Many simultaneous feature checks help explain the high stable alert rate. A better operational version would calibrate the **whole-batch alert rule** on untouched stable batches, separate informational from paging alerts, and evaluate threshold choices on a second independent sample. It should also account for the cost of false alarms and delayed labels.

The simulations reuse rows from a finite held-out pool, and shifted features retain historical labels. `label_shift` flips labels artificially. The degradation definition is a >0.05 recall or F1 drop versus validation, not a statistical proof of real-world failure. The 30 repetitions are not independent population samples; rates and descriptive intervals should not be generalized to live credit decisions.
